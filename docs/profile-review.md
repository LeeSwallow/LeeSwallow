# 프로필 구성과 참고 자료

검토일: 2026-10-27. GitHub 프로필 README 갱신을 위한 편집 기록이다.

## 구성

기존의 학습 소개·기술 배지·통계 카드 중심 구성을 다음 순서로 바꿨다.

1. 이름, 백엔드·AI 서비스 직무, 연락처
2. 업무 이해·실행 추적·실험이라는 일하는 방식
3. HeyMoa → 금정열린배움터 → MoMeet: 서비스, 역할, 문제와 해결, 조건을 붙인 결과
4. 프로젝트에서 사용한 기술
5. 추가 프로젝트 3개, 텀·교육 프로젝트 6개, 비공개 연구·개발 도구 3개
6. 교육과 수상

헤더는 저장소 안의 정적 SVG다. 시각 개편 후 Skill Icons와 Shields.io 배지, 공개 GitHub 활동·언어 카드를 추가했다. 핵심 소개와 기술 이름은 대체 텍스트로도 읽을 수 있다.

## 추가 저장소 검토

후속 요청에 따라 인증된 GitHub CLI로 개인 저장소 32개(비공개 8개 포함)의 목록을 확인했다. 비공개 8개는 파일 트리·진입 문서를 확인하고, 추가 후보의 README·의존성·구현 파일을 읽었다. 조직 저장소는 접근 가능한 목록을 조회한 뒤 본인 작업과 관련된 HeyMoa 하네스·온톨로지 등을 선별했다. 모든 조직 저장소의 코드를 전수 검토한 것은 아니다.

- 추가 반영: Detective Agent, Detox-Agent, SmartHome-MCP, Emotion Diary, PDF Summarizer, Pomodoro Todo, 공공데이터 분석, FPGA 두더지 게임.
- 비공개 작업 요약: HeyMoa 하네스·온톨로지, 개인 LLM Wiki 도구. 원문·코드·비공개 저장소 링크는 공개 README로 옮기지 않았다.
- 개인 비공개 저장소의 나머지는 학습·코딩테스트·강의 실습·지식 기록이 중심이라 독립 제품 경력으로 나열하지 않았다.
- 텀 프로젝트 표는 저장소가 다루는 구현 주제이며, 모든 부분을 본인이 단독 작성했다는 의미가 아니다. 개인 담당 근거가 있는 Detective Agent·Detox-Agent는 담당 범위를 별도 표기했다.
- Emotion Diary는 Android Kotlin 소스와 Python MCP 백엔드, 공공데이터 분석은 인구·사고 분석 노트북과 지도 시각화 의존성을 확인했다. FPGA 게임은 설계 문서와 Verilog 모듈을 확인했다.
- 강의 포크, 내용이 중복되는 초기 과제, 뼈대 수준의 TaskPulse-Agent는 추가하지 않았다. stickypane의 기존 공개 전 점검 보류는 유지했다.

이번 확인은 문서·소스 기반이다. 추가 프로젝트를 실행하거나 배포 상태·성능·개인 기여율을 새로 검증하지 않았다.

## 시각 개편

텍스트가 많다는 피드백에 따라 기존 본문을 `project-details.md`로 보존하고, 프로필은 언어·도구 아이콘, 연락·기술·교육 배지, 대표 프로젝트 2×2 카드, 짧은 프로젝트 목록으로 바꿨다. 비공개 작업은 접을 수 있도록 정리했다. 수치와 조건의 상세 설명은 프로젝트 상세 문서에 남겼다.

- [Skill Icons](https://github.com/tandpfun/skill-icons): 언어·백엔드·배포 도구 아이콘.
- [Shields.io](https://shields.io/): 연락처·기술·교육 배지.
- [GitHub Readme Stats](https://github.com/anuraghazra/github-readme-stats): 공개 활동과 공개 저장소 언어 카드.

외부 이미지 서비스 상태에 따라 아이콘·배지·통계가 일시적으로 표시되지 않을 수 있다. GitHub 활동·언어 통계는 공개 범위이며 숙련도나 비공개 작업량을 뜻하지 않는다. 자동 생성 트로피·연속 기여·조회수 배지는 추가하지 않았다.

## GitHub 프로필 중심 재구성

포트폴리오 형태라는 피드백을 반영해 역할·팀 규모·학력·수상과 프로젝트 설명 카드를 프로필 첫 화면에서 제거했다. 현재 작업의 실제 앱 아이콘 2개, 기술 아이콘, 실제 저장소 메타데이터 기반 카드 4개, GitHub 활동·언어 카드만 앞에 두고 나머지 저장소는 접었다. 상세 내용은 기존 `project-details.md`에 보존했다.

앱 아이콘 출처: 공개 HeyMoa Web의 `public/apple-touch-icon.png`, petnudge의 `docs/images/generated/icon.png`. 해당 프로젝트를 가리키는 링크와 함께 사용했다. GitHub 계정 아바타나 계정 설정은 변경하지 않았다.

## 프로젝트 목록 복원

프로젝트가 지나치게 생략됐다는 피드백에 따라 이전 커밋(`af32acb`)과 프로젝트 상세 기록을 대조했다. 저장소 카드 4개는 유지하고, 접힌 추가 저장소 표와 비공개 작업 요약 문장을 서비스·앱 6개, 텀 프로젝트·프로토타입 6개, 연구·개발 도구 3개의 펼쳐진 목록으로 바꿨다. 각 항목에는 구현 주제와 기존 기록으로 확인한 역할·기술을 짧게 표시했다.

기존에 공개를 보류한 저장소 링크는 추가하지 않았고, 학습 포크·중복 과제·뼈대 프로젝트의 제외 기준도 유지했다. 이번 변경은 이전 기록의 재구성이며 저장소 공개 상태나 실행 결과를 새로 검증한 것은 아니다.

후속 요청으로 졸업 과제 **온디바이스 낙상 감지 시스템**을 README 목록과 상세 기록에 추가했다. `Recruiting/portfolio/01_프로젝트/낙상감지_졸업과제/README.md`의 최신 최종보고서 기반 역할 구분을 따랐다. 본인 담당은 모델 개발·선정, 후처리, 보드 실행 구조·메모리 배치 검토로 소개했다. 전체 시스템 실시간 성능이나 단독 개발로 표현하지 않았으며, 공개 저장소 링크는 확인되지 않아 넣지 않았다. 목록은 총 16개다.

긴 불릿 목록의 가독성 개선 요청에 따라 16개 항목을 세 개의 표로 재배치했다. 서비스·앱은 서비스 설명과 담당, 졸업·텀 프로젝트는 분류와 구현 내용, 연구·개발 도구는 분류와 목적을 구분했다. 기술은 코드 표시와 셀 내 줄바꿈으로 나눴으며, 추가 설명은 기존 상세 기록의 범위에서 보완했다.

프로젝트별 기술 셀에 기존 Skill Icons 스타일의 32px 아이콘을 추가했다. FPGA 항목은 이름을 표시하는 Shields.io 배지를 사용했다. 기술 이름과 대체 텍스트는 유지하고, 비공개 연구 항목에는 확인되지 않은 기술을 추가하지 않았다.
